# PG 项目优化方向清单

> 用法：从「优先级」里挑 **2–3 个做透**，不要全做。面试时能讲透 2 个 > 列 10 个。
> 本清单是**方向**，不是已完成项。做完再写进简历。

---

## 一、AI 能力（最贴 AI 应用岗 JD）

| 方向 | 具体做什么 | 面试能讲什么 | 优先级 |
|------|-----------|-------------|--------|
| **RAG 检索增强** | 把 `datasets` 里的 Excel/CSV 与历史成功案例向量化，生成前召回相似案例做 few-shot 注入 | 向量库选型、切分策略、召回效果评估 | 高 |
| **Prompt 工程化** | 模板集中管理 + few-shot 示例库 + 输出 schema 校验 + 失败自动重试 | 提示词版本管理、约束解码、失败重试策略 | 高 |
| **多模型路由** | 已有 DeepSeek + Qwen3.5，加"按复杂度路由 + 失败自动降级切换" | 降级策略、成本与延迟权衡 | 中 |
| 流式输出 | SSE 逐步返回生成内容，替换现在的整段等待 | 长请求的体验优化 | 低 |

---

## 二、评估体系（把你要做的实测，顺手固化成功能）

| 方向 | 具体做什么 | 面试能讲什么 | 优先级 |
|------|-----------|-------------|--------|
| **离线评估集** | 固定一批 prompt 做回归测试，每次改完跑一遍 | 有评估意识，而不是"跑通就行" | 高 |
| 质量看板 | 一次通过率 / 语义正确率 / 耗时分位数可视化 | 数据驱动的迭代习惯 | 中 |
| 失败归类统计 | 把失败原因（围栏不闭合 / 编译报错 / 空回复）分类计数 | 定位问题的能力 | 中 |

> 💡 **这条几乎白捡**：你本来就要手测出数字，顺手把它做成系统里的一个页面，数字和功能一起拿到。

## 三、工程硬功（从"能跑"到"能扛"）

| 方向 | 具体做什么 | 面试能讲什么 | 优先级 |
|------|-----------|-------------|--------|
| **编译任务队列化** | 现在是 `child_process.exec` 同步编译、30s 超时会阻塞请求；改任务表 + 前端轮询/SSE 进度 | 异步任务、状态机、超时与重试 | 高 |
| 缓存与限流 | 相同 prompt + 数据集命中缓存；LLM 接口加限流防刷 | 缓存键设计、限流算法 | 中 |
| 编译并发控制 | XeLaTeX 是重进程，加并发上限避免打爆机器 | 资源隔离、背压 | 中 |
| 前端 api 封装层 | 现在是组件直调 axios，抽统一 request 层 + 全局错误处理 | 前端工程化 | 低 |
| 路由守卫 | 14 条路由目前无全局守卫 | 前端权限控制 | 低 |

## 四、可观测与安全

| 方向 | 具体做什么 | 面试能讲什么 | 优先级 |
|------|-----------|-------------|--------|
| 链路耗时拆解 | 把 LLM 调用 / 编译 / IO 分段计时，写进监控页（已有 `system_log`、`api_log` 基础） | 性能剖析 | 中 |
| 上传内容校验 | 现在只限 100MB，可加文件类型与内容校验 | 输入校验 | 中 |
| 编译沙箱 | 现在只做危险序列校验，可加进程隔离 | 安全边界 | 低 |
| 启动配置校验 | `.env` 必填项缺失时启动即失败；顺带把 `cors`、`multer` 补进 `package.json` | 配置治理、依赖管理 | 低 |

---

## 只做三个的话，推荐这个组合

**RAG 检索增强 + Prompt 工程化 + 编译任务队列化**

理由：

1. 前两个直接对标 AI 应用岗 JD 里的高频关键词
2. 第三个把项目从"能跑"讲到"能扛"，是工程素养类问题的弹药
3. 三者都有清晰的**前后对比数据**可讲，正好接上你要做的实测
