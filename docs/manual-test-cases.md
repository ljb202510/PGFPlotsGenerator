## 1. 目的与范围

验证系统**核心链路**是否可用：

```
注册/登录 →（可选）上传数据文件 → 输入提示词 → AI 生成 PGFPlots 代码
        → 编译为 PDF → 在线预览图表是否正常
```

共 **10 个简单用例**：

- **用例 01–08**：带配套数据文件上传（CSV 与 Excel 混合，验证两类格式解析）。
- **用例 09–10**：不传文件，验证“无数据集也可基于公开/自带数据出图”。

## 2. 前置准备

测试前请按 `README.md` 第 4 章启动环境（路径相对 `hello/`）：

```bash
# 1. 初始化数据库（库名 X，会 DROP 重建）
mysql -u root -p000
mysql> source 1.sql;
mysql> source migrations/add_notice_feedback_columns.sql;
mysql> source migrations/create_notice_read_table.sql;
mysql> exit;
cd backend && node migrations/001_conversations.js && cd ..

# 2. 启动后端（终端 A）
cd backend
copy .env.example .env   # 至少填写 JWT_SECRET（Linux/macOS 用 cp）
npm install
npm run dev              # http://localhost:3000

# 3. 启动前端（终端 B，回到 hello/ 根目录）
npm run serve            # http://localhost:8080
```

准备事项：

1. 打开 `http://localhost:8080`，注册一个**普通用户账号**并登录（如已有账号可复用）。
2. 数据文件位于 `docs/testdata/` 目录下（与本文档同级）。共 8 个：5 个 `.csv`、3 个 `.xlsx`。
3. 默认模型为 **Qwen3.5**；如某用例连续失败，可点击页面左下“当前模型”切换为 **Deepseek-V4-Flash** 重试。

## 3. 通用测试流程

每个用例按以下步骤操作（“上传数据”一步仅带文件用例需要）：

1. 登录后进入 **AI图表助手** 页面（首页即图表生成页）。
2. 带文件用例：点击输入框下方 **「点击上传」** 选择 `docs/testdata/` 下对应数据文件；上传成功后会提示“已自动选择文件”。
   - 无文件用例：直接进入第 3 步，不选择任何文件。
3. 在输入框中**原样复制**该用例的提示词（见“提示词”小节）。
4. 回车或点发送按钮，等待 AI 思考结束（输入按钮出现“停止”方块期间属正常生成中）。
5. 等待 AI 回复：应出现「生成的 PGFPlots 图表代码」区域与“历史记录已保存”提示。
6. 点击代码区 **「生成PDF」** 按钮，等待编译（按钮转圈）。
7. 弹出 **PDF 预览** 对话框后，检查图表是否正常显示。
8. 关闭预览，在末尾的“测试结果记录表”中记录结果。

## 4. 通用通过标准

对每个用例，同时满足以下条件即判定**通过**：

1. **无红色错误气泡**，AI 正常返回内容且包含可识别的 PGFPlots/LaTeX 图表代码。
2. 出现“历史记录已保存”提示；点击「生成PDF」出现“PDF生成成功”提示，并弹出可正常打开的 PDF 预览。
3. **PDF 图表渲染正常且符合语义**：
   - 图表标题、X/Y 轴标签（或饼图扇区标签）存在且为中文，无乱码；
   - 图内数据与上传数据（或提示词中数据）一致，量级、单位匹配；
   - 有数据点标记时有数值标注；多系列/多分类时图例不遮挡数据主体；
   - 非空白图、无缺失、无编译错误弹窗（弹窗内不出现 `!` 开头的 LaTeX 报错）。
4. 用例专属“验证要点”全部满足。

> 判定辅助：PDF 可放大查看；若怀疑数据不对，可对照第 6 节中该用例的“数据预览”。

## 6. 用例明细

### 用例 01：月度销售额折线图

- **目的**：验证上传 CSV 后能生成并编译单系列折线图，趋势与数据点正确。
- **数据文件**：`docs/testdata/01-line-sales.csv`
- **数据预览**：月份（1–12 月），销售额（万元）＝ 86, 92, 105, 98, 112, 126, 119, 138, 150, 143, 162, 175。
- **提示词**：

```
请根据我上传的数据绘制折线图，展示 1—12 月销售额的变化趋势；折线添加数据点标记并在每个数据点上方标注销售额数值（单位：万元）；添加图表标题、X 轴（月份）与 Y 轴（销售额/万元）标签，并加上图例。
```

- **验证要点**：
  1. 折线含 12 个数据点，数值与上表一致；
  2. 每点上方有数值标注、不互相重叠，整条线走势符合数据（整体上行、3 月回落后再升）；
  3. 中文标题与坐标轴标签正常显示。

### 用例 02：各车间产量柱状图

- **目的**：验证 CSV 上传后柱状图分类轴与数值标注正确。
- **数据文件**：`docs/testdata/02-bar-workshop.csv`
- **数据预览**：一车间 4520、二车间 6100、三车间 3890、四车间 5230、五车间 2980（台）。
- **提示词**：

```
请根据我上传的数据绘制柱状图，对比各车间产量；在每根柱子上方标注产量数值（单位：台）；添加图表标题、X 轴（车间）与 Y 轴（产量/台）标签，并加上图例。
```

- **验证要点**：
  1. 5 根柱子，高度从高到低为二车间 > 四车间 > 一车间 > 三车间 > 五车间；
  2. 柱顶数值标注清晰（无边框遮挡、不与标记重叠）；
  3. Y 轴范围合理，最高的二车间（6100）完整显示在轴内。

- **提示词**：

```
请根据我上传的数据绘制饼图，展示各品牌市场份额占比；为每个扇区标注品牌名称与百分比数值；添加图表标题与图例。
```

- **验证要点**：
  1. 饼图含 5 个扇区，占比大小与数据一致（A 最大、E 最小）；
  2. 各扇区标签含品牌名与百分比，合计约 100%；
  3. 中文字体与图例渲染正常。

### 7.1 首轮实测问题与修复记录（2026-09-09）

> 记录首轮实测（10 个用例）期间发现并已修复的问题；除下列条目外，其余均一次通过。以下修复仅影响“新生成请求/后续编译”，不影响历史数据。

#### 用例 02 · 柱状图编译失败（`PDF生成失败`）
- **现象**：点「生成PDF」提示失败，错误提示仅显示 XeTeX 启动横幅（Toast 只展示前 300 字符，真实 LaTeX 报错被截断）。
- **原因**：`compileToPDF` 错误文案 `slice(0,300)` 截断；同时彼时系统提示未严格约束 AI 输出结构与标注样式，编译链路更易踩坑却难以定位。
- **解决方案**：错误 Toast 改为完整展示；编译失败样本与日志留档 `backend/storage/debug/`；系统提示 PE 重构（禁止文档脚手架、修正数值标注样式键）+ 编译外壳加固（预处理无条件清理 `\documentclass/\usepackage`、预置 `pgf-pie`）。
- **复测**：通过。

#### 用例 03 · 饼图双层文档结构导致无饼图
- **现象**：AI 输出的是完整 LaTeX 文档（`\documentclass{standalone}`、`\usepackage{pgf-pie}`、`\begin{document}…\end{document}`），PDF 只渲染出孤立的“数据来源”注记。
- **原因**：AI 输出了文档脚手架，被后端再次包裹形成双层 `\documentclass`；旧 `preprocessLatexCode` 仅在含 `\begin{document}` 时才清理，且外壳未预置 `pgf-pie`。
- **解决方案**：系统提示【输出内容边界】禁止输出文档脚手架并说明预置宏包；`preprocessLatexCode` 无条件行级清除 `documentclass`/`usepackage`；编译外壳预置 `\usepackage{pgf-pie}`。
- **复测**：通过。

#### 用例 04 · 散点图数值标注覆盖数据点 / 偶发缺失
- **现象**：数值标注带白底黑框、盖住数据点；偶发完全不显示数值标注。
- **原因**：提示词使用无效键 `nodes near coords style=`（正确键是 `every node near coord/.append style=`）；对“有 `mark` 必配数值标注”约束不足。
- **解决方案**：系统提示 R3 改为正确样式键并要求无边框无底色（`fill=none, draw=none, inner sep=1pt, anchor=south`），加入正反例与输出前自检，强制标注成对出现。
- **复测**：通过。

#### 用例 05 · 分组柱状图柱子全挤到中间 + 上传050607时 `Data too long`
- **现象（图）**：x 轴刻度变成一整串“一季度，二季度，三季度，四季度”，8 根柱子全部堆在中间。
- **原因**：`symbolic x coords` 列表使用了**全角中文逗号 `，`**，pgfplots 仅以英文半角逗号 `,` 分隔，于是把整串文字当作**单个分类**。
- **解决方案**：系统提示新增 R7——`symbolic x coords` 列表必须用英文半角逗号分隔并附反例。
- **现象（上传）**：上传该文件报 `Data too long for column 'data_name'`。
- **原因**：`data_name` 列原为 `VARCHAR(20)`，文件名去扩展后 22 字符超长。
- **解决方案**：迁移扩列到 `VARCHAR(50)`（`migrations/alter_data_file_data_name.sql`，存量库已执行，`1.sql` 已同步）；`datasets.js` 上传/改名接口对超长名兜底截断到 50；`DataUpload.vue` 输入框 `maxlength="50"`。
- **复测**：通过。

#### 用例 06 · 双折线数值标注互相压盖
- **现象**：两条折线同时标注，在 Y 值接近/交叉的点位（如 6 月 76/75、7 月 90/84）数字互相压盖并贴住线条/数据点。
- **原因**：两条 `\addplot` 共用 axis 级同一个 `every node near coord` 样式且都 `anchor=south`，标在同一侧。
- **解决方案**：系统提示新增 R8——多系列折线（≥2 系列且 X≥8）按系列错开：y 较大系列 `anchor=south`（标上方）、较小系列 `anchor=north`（标下方），字号 `\tiny`/`\scriptsize`，附双 `\addplot` 示例与反例。
- **复测**：通过。

## 9. 进阶用例（v1.2 扩展，2026-09-10）

> 本节在 §1–§8 的 10 个基础用例之外，从第一性原理扩展故障面覆盖。**通用流程、通过标准、前置准备完全沿用 §2–§4**，不再重复；数据文件与基础用例同级（`docs/testdata/`）。

### 9.1 设计原则

基础用例 01–10 已证明「常规链路可用」；进阶用例聚焦**已修复缺陷的回归**与**尚未覆盖的边界**，按三轴展开：

1. **生成规则轴（R1–R8）**：系统提示（`backend/routes/chat.js`）中 8 条渲染规则各设一个易触发反例的场景，防止日后调整提示词或编译外壳时规则悄悄失效。
2. **数据形态轴**：负值、单数据点、多分类（>10）、超长中文标签、极小/极大值悬殊、小数/百分比、退化值（全相等/含 0）——这些是 AI 生成代码最易踩坑、也最难在常规数据里暴露的形态。
3. **图表类型轴**：面积图、水平条形图、直方图、误差棒柱状图、对数轴折线、平滑曲线、堆叠面积图、百分比堆积柱状图——扩展编译外壳已预置宏包（pgfplots / pgf-pie）可原生支持、但基础用例未覆盖的图型。

> 分工：进阶用例**不重复** 01–10 已覆盖的单系列趋势 / 分类对比 / 占比 / 相关性 / 多系列 / 堆积 / 大数值等常规链路；数据可复用时优先复用，避免文件膨胀。
>
> 兼容性提醒：编译外壳仅预置 `pgfplots`、`pgf-pie`、`amsmath`、`amssymb`、`xcolor`、`fontspec`、`xeCJK`，**未加载任何 pgfplots library**；故进阶图型只使用上述宏包的原生能力（`ybar/xbar/hist/error bars/log axis/smooth/填充折线/堆叠`），不要求 AI 额外引入宏包。
