## 三、六类缺陷（全部已修）

### 缺陷 1｜`xbar` 坐标顺序反 —— 477 空图

`xbar` + `symbolic y coords` 时坐标必须是 `(数值, 分类)`，模型写成了 `(分类, 数值)`：

```latex
symbolic y coords={上海,北京,...},
\addplot[...] coordinates {
    (上海,831)     % ← 错：x 位置放了字符串
```

pgfplots 无法把「上海」当 x 数值 → **数据点整批丢弃** → 只剩空轴，Y 轴分类还错乱成「北京/北京/北京/上海/上海/上海」。**不报错。**

### 缺陷 2｜非法色名静默变黑 —— 477

```latex
\addplot[fill=steelblue, draw=steelblue] ...
```

`steelblue` **不是 xcolor 的合法色名**（svgnames 里是首字母大写的 `SteelBlue`）。日志里只有一行
`! Package xcolor Error: Undefined color 'steelblue'.`
填充**静默回落成黑色**，**编译照样"成功"、照样产出 25KB PDF**。

> 这与项目此前登记的 `\usepackage{xcolor}[dvipsnames,svgnames]` 位置错误属于**同一类静默失败**。

### 缺陷 3｜字面 `\n` 未还原 —— 490 纯白纸

代码里存在**字面 `\n`**（反斜杠 + 字母 n 两个字符）：

```latex
...anchor=south}]\ncoordinates {
```

`\n` 让 axis 选项解析在此处断掉，整张图被吞掉 → `hist490.pdf` 只有 **873 字节 / 2 页白纸**。

**为什么没被自动修好**：`ChartCodeExtractor.normalizeEscapes` 的守卫是「**后面不跟 ASCII 字母**」（为保护 `\node`/`\times`），而这里的 `\n` 后面紧跟 `c`（`coordinates` 的 c）——**正好落在盲区**。**这是真 bug，会稳定复现。**

### 缺陷 4｜注记写成文件名 —— 482 / 493 / 494

```latex
{数据来源：18-pctstack-expense.xlsx}     % 482
{数据来源：29-longlabel-regions.xlsx}    % 493
{数据来源：30-extreme-invest.csv}        % 494
```

作为范例入库会**教模型把内部文件名写进图表**。已统一改为 `数据来源：根据上传数据`（与 496 一致的口径：不编造来源）。

### 缺陷 5｜注记位置错 / 注记根本不渲染 —— 10 例

这是**最隐蔽、最普遍**的一类。`\node ... at (axis description cs:0.0,-0.15)` 有两种坏法：

| 写法 | 后果 | 涉及 |
|---|---|---|
| `\node` 放在 `\end{axis}` **之后** | 坐标系已失效 → `! Undefined control sequence`，节点位置**纯属巧合地**落在左下 | 477、478、480、491、493、494、496 |
| `\node` 放在 axis **内** | 不报错，但文字被排版到 **nullfont**（日志里满屏 `Missing character ... in font nullfont`）→ **PDF 里能提取到文字、但画面上什么也没有** | 476、481、482、489、490、495 |

**修正写法**（已用于全部 14 份）：把节点移到 `\end{axis}` 之后，并用与坐标系无关的锚点：

```latex
\end{axis}
\node[anchor=north west, font=\scriptsize] at (current bounding box.south west) {数据来源：...};
\end{tikzpicture}
```

**验证口径**：`pdftotext` 只能证明「文字在 PDF 里」——495 就是「有文字但不可见」。所以**必须目视**（见第四节）。

### 缺陷 6｜两套量纲记法 —— 489

坐标轴用科学计数法（`·10⁵`，刻度 0/0.5/1.0/1.5），柱顶标注用「万」（`13.57万`）。数值本身**一致**（1.357×10⁵ = 13.57 万），但同一张图两套记法，观感混乱、且作为范例不清晰。

**修法**：保持原始数据不变，把坐标轴刻度也改成「万」：

```latex
scaled y ticks=false,
ytick={0,50000,100000,150000},
yticklabels={0,5万,10万,15万},
```

### 缺陷 7｜正负值被拆成两个 `\addplot` —— 491（用例 27 的老问题）

**现象**：X 轴只出现 5 个季度标签（`2023Q1 / 2023Q3 / 2024Q1 / 2024Q2 / 2024Q4`），
**负值那三个（`2023Q2 / 2023Q4 / 2024Q3`）的标签不见了**；柱子还被横向错开半个柱宽。

**根因**：AI 为了区分正负值，把同一组季度数据拆成两个 `\addplot`：

```latex
\addplot[fill=green!60!black, ...] coordinates { 5 个正值 };   % 2023Q1/2023Q3/2024Q1/2024Q2/2024Q4
\addplot[fill=red!80,        ...] coordinates { 3 个负值 };   % 2023Q2/2023Q4/2024Q3
```

pgfplots 把每个 `\addplot` 当作**分组柱的一个系列**：

1. `xtick=data` 只从**其中一个系列**取分类 → 另一半 X 轴标签消失；
2. 两个系列各被**横向偏移半个柱宽** → 柱位与分类对不上。

**这已经导致过一次真实事故**（checklist 用例 27），项目为此写了预处理 `mergeSplitYbarAddplots`：
按「ybar 非 stacked + ≥2 个 addplot + 各 addplot 的 x 两两互不重叠」判定后，
**取第一个 `\addplot` 的选项、把所有坐标并进一个 addplot**。

> ⚠️ **但合并只保留第一个 `\addplot` 的样式**——所以原版（走生产流程编译的 `hist491.pdf`）
> 会出现「**8 个标签都对、但所有柱子都是同一个绿色**」，这就是"原版颜色有问题"的由来。

**修法**：正负值写进**同一个** `\addplot`。负值写成负坐标，柱子自然向下延伸——
"方向相反"本身就是区分，不需要拆系列：

```latex
\addplot[fill=blue!60, nodes near coords] coordinates {
    (2023Q1,120) (2023Q2,-85) (2023Q3,210) (2023Q4,-40)
    (2024Q1,260) (2024Q2,180) (2024Q3,-30) (2024Q4,320)
};
```

**最终采用双色方案**（`hist491-fixed.tex`）：两个 `\addplot` 的 **x 集合完全相同**（缺失值补 0）
＋ `bar shift=0pt`，靠 `point meta=explicit symbolic` 的**空标签 `[]`** 抑制 0 值柱的数值标注。
这样既能「正绿负红」，又**不会被 `mergeSplitYbarAddplots` 合并**（x 有重叠 → 触发保护判据）。

```latex
\addplot[fill=green!60!black, bar shift=0pt, nodes near coords, point meta=explicit symbolic]
    coordinates { (2023Q1,120)[120] (2023Q2,0)[] ... (2024Q4,320)[320] };
\addplot[fill=red!80, bar shift=0pt, nodes near coords, point meta=explicit symbolic]
    coordinates { (2023Q1,0)[] (2023Q2,-85)[-85] ... (2024Q4,0)[] };
\legend{盈利, 亏损}
```

实测：**8 个 X 标签全在、柱位正确、编译零错误、注记可见。**

## 六、这对「入库闸门」意味着什么

我们此前设计的 `verified` 等级 = **编译成功 且 静态零违例**。但：

| 案例 | 编译成功 | 静态违例 | 会被判 `verified` | 实际质量 |
|---|:---:|:---:|:---:|---|
| 477 | ✅ | 无 | ✅ **会** | 空图 |
| 490 | ✅（产出 PDF） | 无 | ✅ **会** | 白纸 |
| 478/480/491/496 | ✅（有报错但也有 PDF） | 无 | ✅ **会** | 注记位置错 |
| 482/489/495 等 | ✅ | 无 | ✅ **会** | 注记不可见 |

> **即「verified」这个自动判据同样会把垃圾判成合格。**
> 我们此前给 `user_id=1` 定的 20 条 `verified`，**里面很可能也有同类垃圾**——判据一样。

这反过来证明：**唯一可靠的判定者是「人 + 亲眼看过图」**，这也正是本审核包存在的意义。
